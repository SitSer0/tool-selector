# Tool Selector

Минимальное тестовое: выбор инструментов из большого каталога и воспроизводимая оценка качества. Итоговая версия использует **только готовый ToolBench Retriever и английские запросы**. Один API endpoint, один запуск евалов, один файл результатов. Исполнения тулов, агентного цикла, reranker и облачного инференса нет.

## Запуск

Проверено на Python 3.11.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m tool_selector.prepare
uvicorn tool_selector.api:app --host 127.0.0.1 --port 8000
```

Первый `prepare` скачивает зафиксированную модель (~430 MB) и строит индекс. На Mac с Metal используйте `python -m tool_selector.prepare --device mps`, чтобы ускорить индексацию. Повторная подготовка использует кеш. После подготовки интернет не нужен; все запросы обрабатываются на CPU.

В текущей рабочей папке модель и индекс уже подготовлены. Модель, индекс и токенизатор находятся в `.cache/`, окружение — в `.venv/`; эти служебные папки не входят в исходный код.

## API

`POST /select-tools`: непустой английский `query` до 8000 символов; `top_k` от 1 до 100, по умолчанию **15**. Это максимум возвращаемых инструментов. Ошибки ввода — 422. Кириллический запрос получает 422 с просьбой написать по-английски. Полноценного автоматического определения языка нет; остальные языки также не поддерживаются.

Контрольный пример из тестового набора (ToolBench query 213):

```bash
curl http://127.0.0.1:8000/select-tools \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{"query":"I'm planning a weekend getaway and need to find a nearby hotel. Can you recommend a hotel with good ratings, provide its name, address, phone number, and distance from my location?","top_k":15}
JSON
```

Ответ содержит `tools` с `tool_id`, `name`, `description`, полной сохранённой `input_schema` и `catalog_version`. Внутренний поисковый текст не возвращается. Swagger: [localhost:8000/docs](http://127.0.0.1:8000/docs).

## Архитектура

`Английский запрос → ToolBench encoder → косинусное сходство с индексом → top-k → определения инструментов`.

Используется [ToolBench/ToolBench_IR_bert_based_uncased](https://huggingface.co/ToolBench/ToolBench_IR_bert_based_uncased), revision `cf4a904c33cde549643aa6d9091146e68ed4932f`, без дополнительного обучения. Mean pooling, нормализованные векторы размерности 768, длина входа 256 токенов из конфигурации модели. Поиск точный через NumPy, без отдельной векторной БД.

Индекс хранится в одном `.cache/index.npz`. Fingerprint включает версию модели, ID, порядок и поисковые тексты. После изменения каталога повторите `prepare`: API не использует отсутствующий или устаревший индекс. Пути можно изменить через `CATALOG_PATH` и `CACHE_DIR`.

## Евалы

```bash
python -m tool_selector.evaluate
python -m pytest -q
```

Полный прогон проверяет **881 английский запрос** на каталоге **13 862 инструментов** и перезаписывает `results.json`. Для фиксированной короткой выборки: `python -m tool_selector.evaluate --limit 100` (seed 42).

Метрики:

- **Recall@k** — средняя по запросам доля найденных размеченных инструментов.
- **Полный набор@k** — доля запросов, где найдены все размеченные инструменты.
- **p50/p95** — задержка одного прогретого поиска top-20 на запрос, без HTTP, загрузки, индексации и подсчёта токенов. Другие k вычисляются по префиксам той же выдачи.
- **Контекст** — число токенов полных выбранных определений, фиксированный токенизатор `cl100k_base`, без обвязки конкретного LLM API.

Итоговые значения полного прогона находятся в `results.json`; ниже приведена его сводка.

| k | Recall@k | Полный набор@k | Средний контекст, токены |
|---:|---:|---:|---:|
| 5 | 81.53% | 66.29% | 693 |
| 10 | 91.40% | 82.41% | 1396 |
| 15 | 95.02% | 89.67% | 2095 |
| 20 | 96.94% | 93.53% | 2787 |

Первый k с Recall >= 95% на этом наборе — **15**. Задержка p50 — **38.9 мс**, p95 — **49.0 мс** на CPU, 4 потока Torch.

В JSON также сохраняются выдачи каждого запроса, версии библиотек, хеш запросов, версия каталога, параметры модели/индекса и кривая Recall для k=1…20. Индексация может использовать GPU, но измеряемый поиск выполняется на CPU.

## Данные и ограничения

`data/tools.jsonl` — определения инструментов и внутренний `retrieval_text`; `data/queries.jsonl` — английские запросы с эталонными ID. Одна вызываемая API-операция считается одним инструментом.

Источник: [mteb/ToolBench](https://huggingface.co/datasets/mteb/ToolBench), revision `6f868e5b4c46a9f04c89f7179ddc7c8f162c1068`. Из 1100 запросов используется та же 80% test-часть: seed 42, точные нормализованные дубликаты группируются перед разделением. Если данные отсутствуют, `prepare` восстанавливает их из зафиксированного источника.

Порядок полей поискового текста соответствует [обучающему коду ToolBench](https://github.com/OpenBMB/ToolBench/blob/master/toolbench/utils.py): категория, сервис, API, описание, обязательные/необязательные параметры, ответ. В MTEB имя сервиса и API объединено: объединённое имя помещено в слот API, отсутствующий слот сервиса оставлен пустым. Это адаптация к нашему каталогу, не точное воспроизведение статьи. JSON-схемы восстановлены из параметров источника; неизвестные типы преобразуются в string.

**Область результата — данный английский benchmark.** Модель обучалась на ToolBench; независимость её обучения от этой версии benchmark отдельно не подтверждена. Высокий Recall здесь не доказывает такую же точность на новых запросах, других каталогах и перефразированиях. Известен провал даже на коротком английском запросе `Find nearby hotels and get their contact details`; это ограничение модели, а не исправленная возможность.

Разметка может не учитывать другие корректные инструменты. Покрытие размеченных ID не равно успешному выполнению задачи: совместимость вызовов и исполнение не проверяются. Отказ для запроса вне каталога не реализован — возвращаются ближайшие кандидаты. Прототип оценивает поиск инструментов и не заявляет готовность к универсальному production-использованию.

## Структура

- `tool_selector/`: API, формат каталога, поиск, подготовка и евалы.
- `tests/test_app.py`: проверки контракта API, валидации, метрик и fingerprint.
- `data/`: два файла — каталог и тестовые запросы.
- `results.json`: один итоговый прогон.
- `requirements.txt`: зависимости.
